# P0-05 example and answer decision

The eight entries in [examples.json](examples.json) are **draft specification fixtures**, one practice and one distinct assessment family per proposed outcome. They cover both Serbian scripts, a multi-token target span and candidate answer variation. Neither the Serbian sentences, Russian translations nor answer alternatives have passed the item-level internal source, variant, translation and rights checks in `docs/learning/solo-development-readiness.md`. The source manifest permits analysis only. Publication validation therefore fails deliberately. No fixture is loaded by the app.

For the present scope, `UsageExample` already embeds text, translation and optional target annotation in a catalog sense/construction. A future issued activity can snapshot its exact prompt, target, family and answer policy. File IDs and revisioned pack data provide editorial identity without a new table. **P1-03b trigger:** show a concrete case where the same reviewed example must be reused across independently versioned targets or withdrawn independently of its owning sense/construction, and where file revisions plus embedded examples cannot preserve active references. No such case is demonstrated by these fixtures.

Representative sanitized legacy shapes in `backend/tests/test_domain_catalog.py` include a two-line Serbian blob with a two-line Russian blob, a translation-only blob, and a Serbian example with no translation. The bootstrap stores each raw blob as one `LegacyExamplePayload`; the fingerprint includes both fields. A hypothetical unequal two-line Serbian/one-line Russian blob remains readable as raw text, but line-by-line pairing is not justified. This P0 work does not split, align, rewrite or promote any legacy blob.

Before P1 publication, record direct source locators for each construction and phrase, a second independent description for nontrivial claims, separate language/translation/answer decisions, and an author agreement or other medium-specific permission. Unresolved variants are excluded from automatic binary scoring. Assessment prompts must be editorially distinct beyond a script swap or a family ID change.
