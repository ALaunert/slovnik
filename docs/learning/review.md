# Review of the learning-system research and roadmap

Reviewed 2026-09-24 against the current checkout, the [accepted ADR](../adr/ADR-language-assistant-domain-model-2026-08-26.md), [product state](../product-state.md), and all six learning documents. This is a design and source-code review, not a deployed-data audit or evidence of learning gain. The revised [roadmap](roadmap.md) and [P0 implementation plan](implementation-plan.md) incorporate the decisions below.

## Overall judgment

The four-context modular monolith, deterministic selector, immutable evidence, small written pilot, and explicit separation of exposure, self-rating and scored response fit the repository. The [research synthesis](research.md) supports retrieval across time, task-aligned input/practice and independent assessment as general directions. It does **not** validate this product's four-outcome order, a three-success readiness rule, a particular interval, a corpus-first content strategy, or a proficiency claim. Those remain hypotheses or editorial choices. The [CEFR Companion Volume](https://rm.coe.int/common-european-framework-of-reference-for-languages-learning-teaching/16809ea0d4) provides descriptor scales, not a Serbian syllabus; the draft pilot's cited scales/pages are plausible, but a Serbian L2 educator must approve their use for this written pilot.

## Task size and missing prerequisites

- **P1-04 is two review units:** transaction-safe publication mechanism, then editorial pack activation. The first must be exercised against populated catalog/curriculum fixtures.
- **P1-05 is at least two review units:** bounded deterministic answer policy and gated backend lifecycle; then Vue rendering, state recovery and accessibility. The current four operations can be reused; adding open production or listening is a separate contract change.
- **P1-09 is three deliverables:** supervised local flow, consented delayed-probe protocol/export, then human evaluation/report. Recruitment and 7-/28-day outcomes cannot be completed in one engineering change.
- **P2-01 and P2-02 are release prerequisites for remote/public learner history**, even though their numeric priority follows the local pilot. Production flags must not be set to bypass identity or lifecycle work.
- **Before any new example table or catalog reconciliation**, inventory real legacy example shapes and stale mappings on a sanitized, representative database. Document zero/unequal bilingual lines, edited words and existing activity references. Review whether a file-backed manifest plus existing embedded examples meets the pilot need first.
- **Before direct practice writes**, define a new route-specific deployment/ownership gate and event retention for the supervised local setting. The existing shadow flag does not gate a new API route. A local environment variable alone does not make a remotely reachable service safe for unauthenticated histories.
- **Before P1 publication**, a qualified Serbian L2 reviewer must approve outcome mappings, candidate examples, answer variants and holdout separation. Teacher approval is an external gate, not a dependency for writing the P0 draft.

## Data preservation and migration risks

1. Keep `vocabulary_items`, `user_word_progress`, quiz attempts/answers and their APIs authoritative until an explicit switchover. Do not rewrite old `question_plan` JSON with keys inferred from today's vocabulary; label it legacy. Keep the old score field as a practice score while additive fields are introduced.
2. Keep original example/translation blobs. Line-by-line splitting can mispair unequal lengths; catalog bootstrap is creation-only and [mapping audit](../../backend/app/services/catalog_mapping_service.py) rejects stale, missing or ambiguous mappings. Do not silently reconcile published senses or transfer learner evidence to a changed meaning.
3. Any later additive content table must define an export/restore path and safe downgrade behavior. A migration that drops populated new tables is not data-preserving merely because Alembic can run `downgrade`. Rehearse upgrades against representative populated data and disposable PostgreSQL as well as SQLite.
4. New activity snapshots must pin content/answer-policy versions without exposing private keys. Retiring or withdrawing content affects future selection; historical events and already-issued snapshots need an explicit retention/correction policy. Do not activate production history before identity and lifecycle gates.

## What remains an assumption

The four outcomes, Ekavian baseline, written-only tasks, two scripts, holdout families, readiness occasions and session budget are proposed product/editorial decisions. Corpus frequency and parser output are sample-derived candidates, not level, sense or grammatical truth. A teacher-approved pilot and delayed, independent responses can test some of these decisions; no current test suite or seed content establishes learning effectiveness or full A1 coverage.
