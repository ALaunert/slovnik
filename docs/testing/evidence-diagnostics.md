# P0-06 read-only evidence diagnostics

Version 1 classifies loaded event/activity pairs without changing stored events, projection, selection or scheduling. `app.services.evidence_diagnostic_service.diagnose_events` converts them into pure `EvidenceFact` records; `app.domain.evidence_diagnostics.classify_history` sorts by occurrence and ID, ignores duplicate event IDs, then reports exposure, self-report, retry/repair, assisted, repeated context, independent first response or unknown. A successful retry is a repair only when the loaded parent has a recorded incorrect verdict. Unknown is never failure.

An empty historical hint list does **not** prove no support. Existing shadow snapshots do not record complete hint capture, support timing, stable context family or complete earlier family history, so their deterministic first responses remain `unknown` for independence. A recorded hint without verified timing is `supported_timing_unknown`, not an assisted first response. A known unassisted first answer can remain `unassisted_first_context_unknown` until family lineage is complete. Only a future fully recorded context history can establish `independent_first` or `repeated_context`. Model-only/partial/unresolved outcomes are not promoted to deterministic success.

The six P0-01 synthetic histories, which explicitly provide support timing and complete context families, reconcile to 3/4 independent first, 1/1 assisted, 1/1 repair, 1/1 self-rating positive, 1/1 repeated context and 1/8 unresolved scored submissions. These are specification examples, not historical Slovnik results or validated progress estimates. Projector v1 continues to weight deterministic retries and the legacy scheduler remains authoritative; the diagnostic has no public route or write path.
